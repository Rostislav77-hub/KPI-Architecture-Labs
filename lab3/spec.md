# Специфікація взаємодії — Завдання 3 (UC-01 «Купівля предмета»)

## Мета
Побудувати Sequence-діаграму для прецеденту UC-01 «Купівля предмета» (із Завдання 2) з урахуванням сутностей моделі даних (Завдання 1: `Player`, `InventoryItem`, `MarketTransaction`).

## Учасники взаємодії
- `Player` — актор (покупець предмета).
- `MarketplaceUI` — клієнтський інтерфейс маркетплейсу.
- `TransactionService` — сервіс проведення угоди купівлі-продажу.
- `InventoryService` — сервіс управління предметами інвентарю (`InventoryItem`) та активними лотами.
- `WalletService` — сервіс перевірки та зміни балансу (`wallet_balance` у сутності `Player`).
- `PaymentGateway` — зовнішній платіжний шлюз для поповнення гаманця.

## Основні кроки сценарію UC-01
1. Гравець обирає предмет на маркетплейсі та ініціює покупку через `MarketplaceUI`.
2. `TransactionService` перевіряє параметри лота та баланс гравця (`wallet_balance >= price`).
3. За достатнього балансу кошти списуються, власник предмета оновлюється (`player_id`), а в системі фіксується транзакція.
4. За нестачі коштів система відхиляє покупку та пропонує поповнити баланс через `PaymentGateway` (`<<extend>>`).
5. Якщо предмет уже куплений іншим гравцем, операція скасовується без списання коштів.
